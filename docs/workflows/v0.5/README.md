## 预算与停止

原生新任务默认总期限 1800 秒、模型阶段 1500 秒、收尾预留 300 秒。较短任务将预留封顶为总期限三分之一；可用每日模型时间更少时只减少 worker 时间。总期限不会超过原 task_seconds；日模型时间只预留 worker 部分。未经确认的取消仍占预留与串行位；结算幂等，验证时间不再冒充模型墙钟消耗。旧票据没有新字段时沿用旧期限/结算。

standalone 模型及其工作容器在较早 worker 截止前结束；独立验证使用原总期限。原生协调方若到 worker 截止后才观察到停止，保守失败，不能假定实际上早已停止并消耗收尾窗口。App 的等待应参考返回的 worker_expires，不能用模型自述的完成时间代替观察。原生宿主权限和终止证明限制未解决，预留也不保证测试能在时限内完成。

## 计量与价格

本机 `codex-cli 0.140.0` 的本地 generate-json-schema 确认了 thread/tokenUsage/updated 的 threadId/turnId、tokenUsage.total/last 及五个计数字段。standalone 只接收当前线程/回合的累计 total，缓存输入和推理输出作为子集不重复相加；正常完成且见过用量才标为 reported。重放去重、旧快照不降账、相同事件 ID 不得换内容；最多保存每调用 4096 个事件摘要。失败或缺少最终观测保持 partial/unknown。

原生只提供协调方 `desktop usage TICKET PATH` 接口，PATH 必须为指定 jobs/TICKET/usage-observation.json 的常规文件。须来自实际 App 观察，不接受 Handoff 中的 worker 自报。当前 App 工具未保证提供 token 字段；不存在时保持 unknown，不自动填零、不读原始私聊猜用量。该接口是协调协议，不是进程签名或同用户防篡改边界。

`accounting` 为离线、范围内报告。每个调用有固定 metering 策略和操作人员报价；不内置或联网获取价格。费用为 USD 估算，不是账单；未知模型、缺报价、混合模型或部分用量使完整费用未知。金额以 Decimal 计算，缓存输入从普通输入扣除，推理子集不另收费。按调用开始日归集，不声称能还原跨日账单。

2026-11-02 口径勘误：当前实现按固定的**预留预算日**归集；原生 dispatch 之后可能次日才生成调用记录。预留/账本/退款共享同一天，不按后续读取时的“当天”改写，也不声称是提供方账单日。修复见 [统筹检查](../changes/2026-11-01-006-integrated-audit.md)。

可选 max_observed_tokens_per_call / max_estimated_usd_per_call 默认不启用。达到已观察阈值后停止，取消不清零；配置上限却没有最终用量/所需报价时不能继续接受成功结果/发布。这些是观察后上限，观测前可能已经超出，不能替代提供方预付或强制 token 上限。

## 溯源和兼容

记录包版本、明确的 prompt_revision、准确输入摘要、工具与输出 schema 摘要、派发时源码摘要；源码摘要不是 Git 提交号。standalone 分开记录请求模型与服务端报告模型，原生默认模型未知，协调方有真实元数据时才记录名称。名称不等于不可变模型权重版本。数据缺失不补造；历史调用无追溯账目。

新增两张 CREATE IF NOT EXISTS 表；旧 usage 表和日额度不清零。新增 limits.finalization_seconds 和 metering 可省略使用默认值。仅本地源码、合成/模拟测试；没有修改真实配置、技能、服务、自动化、实时账本或上游。实际验证及回滚见变更记录。
