## 相对 v0.1 的变化

| 节点 | 原行为 | v0.2 行为 |
| --- | --- | --- |
| WF-09 / WF-10 | 报告记录基准与 passed；上游变化重验证 | 成功报告绑定基准、补丁、回归路径、仓库配置、验证规则版本、文件/行数限制；摘要缺失或不匹配时重新独立验证 |
| WF-10 描述修订 | 复用通过的报告 | 要求摘要匹配当前已接受补丁与配置；旧报告或不匹配转为需要关注，不声称补跑测试 |
| WF-02 发布恢复 | 固定 600 秒退避，可持续恢复 | 外部动作前持久计数；退避依次为 600、1200、2400、3600 秒，上限 3600 秒；默认最多 5 次，从首次恢复起累计 86400 秒 |
| WF-02 暂停 | 阻止新工作和写入，未必取消当前聊天 | CLI pause 原子记录暂停和取消意图；即刻 resume 仍保留取消，原生停止确认前不释放预留与串行位 |
| WF-11 发布状态 | 普通更新可能覆盖并发终态 | 使用状态和更新时间条件更新；真实 API 每次写前复查暂停、任务状态与固定范围；在途写入完成记录结果，保留停止终态 |

恢复次数随任务累计，跨聊天、进程和日期保留；日额度仍按配置时区重置。窗口包含等待时间，在下次到期调度检查。未预留的新 PR 等待日额度不消耗恢复次数；原有 publication reservation 语义不变。达到上限保留补丁、报告与发布意图，转为 needs_attention 并去重通知。

实际增量流程：[workflow.mmd](workflow.mmd)。完整目标设计：[design-target.mmd](design-target.mmd)，是 proposal，不能作为已实现功能清单。

## 证据绑定和兼容

控制器以规范化、排序 JSON 计算 SHA-256，规则标识为 independent-red-green-v1。输入包括基准 SHA、各补丁路径和内容、回归路径、完整 Repository 配置、max_files 与 max_lines。验证语义变化须更新规则标识。摘要关联控制器检查，不是 worker 自评，也不是对不可信账本的密码学认证。

旧报告新增字段默认为空。源代码发布恢复自动重新下载并独立验证，无需逐 Issue 审批。描述修订遇到旧报告保守升级为需要关注。镜像仅绑定配置引用，未绑定不可变镜像 ID；重打标签、依赖及外部工具变化仍是限制，不能宣称已实现完整环境证明。

新增 [limits] 配置：publication_recovery_attempts = 5、publication_recovery_seconds = 86400。老配置使用默认值。无数据库结构迁移，新计数与证据使用现有 JSON 字段。

## 延期范围与已知限制

2026-10-31，用户确认以下三项暂不纳入本次验收，也不阻断本批推送：

- 通用阶段队列：当前保留 Desktop/Engine 分入口控制。
- 分仓库累计预算：保留现有每日预算及任务期限。
- 验证专用额度：本批不单独预留验证额度。

其余已知演进边界：

- 单任务全生命周期预算、收尾专用额度、发现和轮询成本核算。
- 通用异常分类及有界返修；未验证中断和质量失败仍保守失败或需要关注。
- 外部授权、pending CI 的独立等待期限；新增窗口只约束发布恢复。
- 不可变镜像/依赖证据与所有路径的强制终止。原生停止仍由 App 协调方确认；已发出的请求不能撤回，GitHub 写入仍有外部竞态窗口。

本批不修改个人配置、已安装技能、监控服务、实时任务或上游 PR。验证和回滚见变更记录。
