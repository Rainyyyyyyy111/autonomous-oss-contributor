# CHG-YYYYMMDD-NNN — 改动名称

| 字段 | 记录 |
| --- | --- |
| 日期与时区 | YYYY-MM-DD，Asia/Singapore |
| 类型 | feature / fix / refactor / docs / policy / baseline |
| 流程版本 | v0.1 → v0.1；流程契约变化则建立 v0.2 |
| 软件版本 | 当前包版本；是否另行发行 |
| Git / PR | 实际提交、标签或 PR；未提交时明确标注，不编造哈希 |
| 需求来源 | 用户目标、Issue 或已核实反馈 |
| 影响节点 | 例如 WF-04 筛选、WF-09 验证；新增节点写清编号 |

## 问题与预期效果

描述触发条件、现有问题、用户可见结果和为何调整；区分已观察事实与假设。

## 修改前后

| 对象 | 修改前 | 修改后 |
| --- | --- | --- |
| 行为/默认值/接口 | 原规则 | 新规则 |

列出涉及模块。流程、状态、权限、预算、门槛或触发条件是否变化？若变化，链接新版本及差异；不变则写明当前版本仍适用。

## 验证与证据

记录实际命令、结果和证据位置。未执行、跳过、模拟适配器和真实运行分别注明。既有测试结果注明来源，不能写成刚刚重跑。文档改动按相关链接、示例和图源一致性检查即可。

## 风险与回滚

记录已知限制、兼容/迁移要求、回退提交或配置方法。回退实现不等于可以回退运行状态。任何人工介入或临时权限/额度例外注明边界、有效期与恢复情况。

## 待观察与结果

明确指标、分子/分母、cohort、观察窗口、对照版本及配置差异。初始写“待观察”；后续追加日期和证据，不将观察结果改写成原先的预测。无样本或缺字段时注明缺失。
