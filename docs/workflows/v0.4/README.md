## 分类与动作

分类来自可信代码异常类型、GitHub HTTP 状态和响应头；不会因 Issue、日志或错误正文写着“retry”“quota”“rate limit”而扩大重试权限。尚未迁移的通用 ContributorError 和无法确定原因的普通 OSError 保持 unknown。

| 类别 | 默认动作 |
| --- | --- |
| invalid_arguments | 返回结构化错误供纠正；不自动重复原参数，仍计入工具保护 |
| permission | 边界违规停止；GitHub 401/403 等认证/权限阻塞暂停，无认证切换 |
| quota | 暂停，不改账号或模型绕过 |
| rate_limit | 持久等待服务端 Retry-After（秒数或 HTTP 日期）/reset；不在模型调用内长时间 sleep |
| transient / timeout | 只有白名单中的安全读取可重试；可能变更状态的调用失败转效果不确定并停止重放 |
| command_failed | 非零命令结果供检查；不据此推断源码缺陷，也不自动重跑（原代码回归红本来可能是预期） |
| validation / conflict / environment / protocol / remote_rejected | 记录失败、停止或升级，不自动重试；404 可由既有可选文件读取语义消费 |
| cancelled / execution_limit / retry_exhausted | 本次尝试终止，原生沿用确认停止协议；不新开替代聊天或清零计数 |
| unknown | 不做底层自动重试；发布的未知外部效果只允许既有有界远端核对 |

错误对象只新增类别、动作和可选等待秒数，不复制原始输入/响应到分类字段。既有 reason、命令日志等仍可能包含目标内容，不构成全面脱敏。worker 不能通过 Handoff 提交授权或控制器错误/验证报告。

## 可重试范围与默认值

自动重试范围是 GitHub GET、代码中精确固定的只读 Issue GraphQL query，以及固定 SHA 仓库下载；GraphQL POST 不能仅凭名称/字符串前缀成为安全读取。其他 GitHub 写请求每次仍检查权限与暂停，单次 API 调用不自动重放。

standalone 的 repo_list/repo_read/repo_search、原生 WorkerTools 的这些工具与 repo_snapshot，可以对明确的瞬时异常重试。repo_apply、regression_write、repo_restore_prior、安装、任意 sandbox_exec、验证测试和模型会话都不自动重放。命令/写入超时不能证明没有副作用；原生请求取消并保留执行位，standalone 退出该会话。

新增 `[limits.retries]`，旧配置使用默认值；本批仅修改仓库示例：

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| max_attempts | 3 | 同一次读取至多三次总调用，包含首次 |
| max_retries | 6 | 共享额度，额外尝试前预留，不因取消或重启退还 |
| max_elapsed_seconds | 15 | 同一次读取的执行与退避累计窗口，上层任务/模型期限更早时服从更早期限 |
| attempt_timeout_seconds | 5 | 每次读取的期限，仍受剩余累计窗口限制 |
| base_delay_seconds | 0.5 | 指数退避起点；采用完整抖动，第一次等待在 0 至 0.5 秒间 |
| max_delay_seconds | 2 | 单次退避上限，绝不延后已有期限 |

每次自动工具重试重新进入 ToolGuard，累计步数、重复次数和无进展；任何执行保护都优先终止，不会被归为瞬时错误。standalone 的工具重试额度随同一修复/修订的各模型阶段共享；原生额度与策略绑定票据，跨工具箱上下文/worker 重启/日期保留。重试耗尽是致命错误，不返回可反复尝试的普通模型工具错误。

GitHub 控制器读取在同一适配器实例共享最多六次额外尝试；新轮询/进程创建的实例会有新的读取额度，这不是跨日或整个服务生命周期预算。原生工具箱内部 GitHub 下载的读取重试接到同一票据持久额度，内部网络请求不另冒充一个模型工具步骤。每层只有一个重试所有者，不给整个 issue/repair/model 阶段再包一层重试。

工具重试在退避前后检查暂停、范围、任务/票据状态与期限，睡眠不持有原生活动状态锁。GitHub 控制器读取每次复查暂停和期限，目标仍由现有范围检查固定，写前范围检查不变。迟到的只读结果不会被当作期限内成功；已发出的变更请求不能撤回，返回的真实外部效果继续按原发布契约记录/核对。

## 发布、兼容和限制

已验证发布遇到瞬时、读取重试耗尽或未知外部效果，沿用 v0.2 的最多五次、24 小时窗口、远端分支/PR 核对及发布写前检查。明确的权限、参数、协议等永久错误转 needs_attention，保留补丁、报告与意图；不靠下个周期继续相同永久错误。认证阻塞还会暂停。

新增报告 error 与工具活动 retries_used/last_error 均有默认值，无表迁移。v0.3 票据若没有 retry_policy，不新增自动重试（一次读取、零额外额度），仍应用当前分类与致命错误处理；更早无工具策略的旧票据不能补造活动证据。验证诊断增加不改变红绿/完整检查标准及摘要规则版本。

分类不是自动根因诊断。未知 Docker/gh CLI 失败若没有明确可信状态，不猜测它是瞬时故障；较慢读取可能触及新期限，需未来经授权配置。该实现没有持久阶段重试队列、通用熔断器或长期监控成本预算。原生宿主工具仍可绕过工具箱，App 停止确认也仍依赖协调方；本批不声称解决这些边界。

本批不修改个人配置、已安装技能、监控服务、自动化或实时账本，不运行生产修复、真实模型或上游写入。验证和回滚见变更记录。
