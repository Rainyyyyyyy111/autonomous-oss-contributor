## 有效性与冲突

`[memory] ttl_days=90、max_context_records=200` 可由一次性配置设置；本批未改实际配置。新行在第一次抽取时固定 expires_at，不按 last_seen 或重复轮询续命。历史行首次在可见授权范围打开账本时按 first_seen + 当前 TTL 固定，条件更新避免覆盖并发观察；之后调整 TTL 不延长已固定的行。

源身份取自控制器适配器的 Review ID，不把任意远端 URL 当身份。带更新时间的 review 使用该时间排序，无时间时用首次检测的本地修订顺序；同条评论改正文但 ID 未变仍有独立版本。明确更新为感谢/撤回/空文本也能覆盖旧建议。不同来源的意见不自动合并为真相；所有分析仍为 hypothesis_requires_validation，只能生成可信模板检查清单，不能授予权限、取消停止终态或替代当前反馈/测试。

TTL 只让记录退出未来检索，默认不自动物理删除。既有聊天已收到的输入和已固定的任务上下文不会被追溯改写。没有新身份/版本证据时不会假装知道维护者意图；不通过历史合并/关闭推断因果。

## 本地失效、删除与审计

- `learning invalidate TASK_ID RECORD_ID`：保留证据并标记失效，重复观察不能使其重新 active。
- `learning delete TASK_ID RECORD_ID`：删除该学习 payload 与旧派生报告，留下记录摘要/源摘要、版本、动作和时间；同样的反馈不能通过 refresh 重新导入。
- `learning audit`：只读、范围内的哈希元数据，不含反馈原文。

已删除最新版的墓碑仍参与版本排序，旧版不能因此重新生效；真正的新版本可形成新记录，删除单条不代表永久屏蔽该来源所有未来意见。记录 ID 必须是已存在的精确摘要，跨白名单/冻结监控身份拒绝。正在被原生任务引用或存在活动 standalone 工作时，治理操作先拒绝，不偷偷改运行中的上下文。

删除前移除已知旧导出，再原子提交 payload 删除、墓碑和审计；导出重建失败明确返回 exports_rebuilt=false，原文旧副本不会留在这些导出路径。拒绝通过链接的 learning 目录操作外部文件。这是逻辑学习库治理，不声称安全擦盘、清除 SQLite/WAL 历史页、其他任务证据、事件、聊天、备份或用户复制的报告。

新增 memory_tombstones/memory_audit 表，不清空任务、processed 反馈、预算或停止状态。回滚旧代码可能不认识墓碑而重新抽取，必须先在副本检查，不能直接重启旧学习流程。实际验证和最终剩余边界见变更/统筹记录。
