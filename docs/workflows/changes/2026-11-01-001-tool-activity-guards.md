## 问题与预期效果

v0.2 有任务期限和每日时间预算，但无法及时停止相同工具/参数重试、交替调用或不断更换查询参数却没有新证据的循环。原生聊天与 standalone 权限/观测入口不同，因此不能只给可选路径加计数后宣称主路径已受保护。

新增共同的 ToolGuard 与原生 WorkerTools，保护命中即停止本次尝试并保存原因，沿用确认停止协议和独立验证，不扩大授权或自动重开聊天。

## 风险与回滚

进展是新结果/工作区字节的启发式，不证明修复有用；重复检查可能拒绝合理的多次复查，默认上限需后续样本校准。命令输出可制造虚假新信息，但不能绕过独立总步数。源码快照摘要增加容器桥接开销；长命令仍依靠原有期限。

原生工作流仍不能强制拦截绕过 WorkerTools 的宿主工具，也不能防同用户改写账本；少量活动记录不证明所有操作受监控。旧票据保持旧协议并标明无追溯计数。取消确认仍由 App 协调方提供，工具返回前已经发生的操作无法撤回。pending 中断、持久化失败或并发调用保守停止，不猜测是否执行成功。

回滚时撤销本批代码和文档，并在状态副本先验证兼容；不要覆盖真实配置或清空计数来重试。新配置字段会被旧严格解析器拒绝，需要在经授权的配置副本移除 limits.tools；本批没有改实际配置。旧代码会忽略新增 job JSON 保护，因此已触发保护或 pending 的票据应先完成停止/人工核对，不得借回滚释放执行位或恢复发布。未创建回滚提交或标签。
