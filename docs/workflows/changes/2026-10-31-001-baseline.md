## 问题与变化

此前已反复迭代 CLI、原生聊天调度、持久恢复、通知、反馈分类、筛选和学习机制，但没有统一的流程版本和逐次变更索引。仅依赖聊天及软件 CHANGELOG 难以回答“某次贡献采用什么流程”“改变了哪一环”“指标能否比较”。

现在建立一个冻结的 Workflow v0.1：总流程图、独立质量链、聊天生命周期、责任/证据映射、默认参数、指标口径和已知边界。同时增加变更模板、索引、贡献约定和项目级 Agent 指引。未来改变流程契约时建立 v0.2；普通修复也记录批次并关联当前流程版本。

本次基线一并保存建档前已完成的实现：候选证据排序及冷却/指派暂缓、未标 Bug 标签候选补充、真实 PR outcome、维护者反馈预防清单、环境预检、离线状态总览，以及此前的原生聊天/通知和发布恢复。首次归档只证明当前快照，不补造它们各自早期的提交时间或因果效果。

## 验证与证据

建档前最近一次实现验证已经完成并在本聊天报告：默认测试 **242 passed / 6 skipped**；真实 Docker 测试 **5 passed**；Ruff、mypy、构建和 wheel 独立安装检查通过。这些是前一轮实现的验证记录，不伪称本轮文档编辑重新执行了全部测试。

本轮验证范围：Mermaid 原始文件与文档图一致；本地文档链接及版本索引有效；manifest 文件存在且 SHA-256 一致；`git diff --check`；基线提交/tag 可定位。没有触发发现、修复、发布 PR、调整 monitor 范围或运行上游目标代码。

## 风险、回滚与未覆盖事项

- 文档可能随代码漂移；后续改动必须更新批次记录，流程变化建立新版本。旧版本勘误追加说明。
- 本轮留档不新增运行安全保证，也不证明长时间无人值守和真实远端 CI 修订场景均已验收。
- 回滚文档规范时可用 Git revert 定位此基线的文档变更；涉及实现回退需同时评估后续数据库/运行状态兼容性，不能把旧源码与新状态盲目拼接。历史标签和记录保留。
- SHA-256 清单用于核对本基线源文件内容；可恢复的源码版本由 Git 提交和标签保存，清单本身不是备份。
