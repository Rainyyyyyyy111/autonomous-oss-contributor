## 问题与预期效果

模型可占满期限挤掉验证，模型墙钟与真实 token/费用没有清晰区分，单次调用的准确提示词和模型身份也缺少可追溯字段。本批将期限在原额度内拆分，并增加带缺失状态的实际观测账本。

## 修改前后

| 对象 | 修改前 | 修改后 |
| --- | --- | --- |
| config / engine / desktop / worker_tools | 单一期限；原生结算可能包含验收时间 | 默认最多预留 300 秒且不超过三分之一；worker 与总截止分离；原生停止确认前不释放执行位 |
| accounting / store / codex | 只有模型秒数 | 新表保存调用溯源、累计用量和去重摘要；当前线程/回合校验，缺失不填零 |
| cli / desktop | 无离线用量或可信协调观察入口 | accounting 范围内只读报告；desktop usage 读取指定协调文件，worker Handoff 不接收计量字段 |
| metering | 无价格来源或已观察上限 | 固定的操作人员 Decimal 报价、明确估算口径；可选观察阈值，未观察/未报价不能假装预算已验证 |

不改变仓库、工具、发布或修订授权；独立红绿标准与验证摘要规则不变。原生宿主能力移除和精确预付费限制仍受平台能力限制，不能宣称完成。

## 验证与证据

本批阶段验证：`uv run pytest -q tests/test_accounting.py tests/test_desktop.py tests/test_protocol_cli_store.py`：**66 passed，14.20 秒**；Ruff 和 mypy（26 源文件）通过。覆盖去重/乱序/跨线程、Decimal 计价、未知和混合模型、错误计数、固定提示词、预留期限、停止后验收、迟到停止和缺用量上限拒绝发布。

本机 `codex --version` 为 0.140.0；在临时目录执行本地协议 schema 生成并读取计量/线程响应字段；没有认证探测、真实模型 turn 或 API 账单查询。最终统筹验证将记录在后续统筹记录，不将此阶段检查冒充最终全量结果。

## 风险与回滚

原生停止观测迟到会保守失败；较短任务的预留封顶三分之一。用量通知可能延迟/缺失，观察上限可能超出；原生无字段时未知。估价不是账单，模型名不是不可变版本；混合模型不重定价整个累计用量。

回滚先在状态副本验证；新增表可保留，不得清空已花预算或恢复已取消任务。旧严格配置解析器不接受新字段，旧代码不识别新 worker 截止语义；应先停止并结算活动票据。账目只对实际记录的新调用，不补造历史。未创建回滚提交或标签。

## 待观察与结果

无生产样本。分别记录原生/standalone 的调用数、reported/partial/unknown 比例、未报价比例、独立验证时间、因收尾或迟到停止失败数、阈值触发数；费用只报有报价的已观测部分，不把模拟用量或旧模型秒数转换为真实 token/账单。
