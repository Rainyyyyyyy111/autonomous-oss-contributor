## 检测定义与默认值

新增配置 `[limits.tools]`，旧配置使用以下默认值；本批只更新仓库示例，不修改个人配置或安装技能：

| 字段 | 默认 | 精确定义 |
| --- | --- | --- |
| max_steps | 120 | 每个修复/修订尝试的已预留工具调用总数；下一次调用在执行前被拒绝 |
| max_repeated_calls | 4 | 相同工具名、规范化 JSON 参数和工作区摘要，整个尝试最多调用四次；交替调用别的工具不清零 |
| max_no_progress | 20 | 连续二十次未观察到新信息的调用，在观察第二十次结果后终止 |

standalone 的评估、回归生成、反馈分类和修复模型阶段共用同一尝试计数。原生路径每个票据单独累计，包含开箱、配置内安装、工具和 snapshot；换工具上下文、worker 重启或跨日期都不清零。错误调用计入步骤和无进展；普通工具错误仍可在剩余额度内纠正，保护异常直接退出模型会话，不能作为可重试错误回传。

调用前持久预留步骤和 pending 标记，完成后持久记录结果。中断留下的 pending 不视作未执行；重开工具箱会保守阻止重试，交接也不能发布不完整活动。控制器独立验证、GitHub 观察/发布和原生等待不计为模型工具步骤；原有时间与预算限制继续有效。

进展仅指成功调用产生此前未见的工作区摘要，或首次出现的成功、非空工具结果。相同读取不会反复算进展；命令只使用成功退出后的输出，忽略 argv、耗时和错误文本；编辑、回归写入、恢复补丁、安装与开箱只根据实际工作区变化判断。失败调用即使改动文件也不算进展；工作区 A→B→A 的回退不算新状态。无法观测工作区时保守终止，不让快照错误变成计数前的无限重试。摘要记录不含原始参数、文件或输出，限额原因不回显工具输入。

这不是语义正确性判断：随机成功输出、无意义的新文件内容仍可能被算作进展，故总步骤上限独立生效。持续无输出、长命令和没有工具事件的模型思考仍由已有期限兜底。

## 原生路径、兼容与边界

WorkerTools 仅接收控制器指定的 job.json 路径，从 SQLite 读取票据、固定仓库配置和基准，通过固定 GitHub 适配器下载文件并在 DockerSandbox 内执行。每次调用检查暂停、期限、运行/停止状态和持久监控身份。regression_write 只写指定回归文件并保持其不变；repo_restore_prior 只恢复票据固定的补丁。工具使用方式见[桌面流程](../../desktop-workflow.md#recovery-and-stopping)。

活动状态存在现有 job JSON；新增表迁移为零。读写短事务使用控制器锁，耗时工具执行在锁外，避免阻塞观察/取消；pending 防止同时或中断后的重复调用，锁争用或结果持久化失败保守保留未完成标记。

保护命中立即保存停止原因、请求取消并发送去重通知。不得自动创建替代聊天或修改发布意图。新 fixed 交接至少需要开箱及一次已完成的工具活动，且不能有 pending 或 blocked；这不证明每个操作都被记录。明确描述修订无须目标执行。升级前没有 tool_policy 的旧票据继续原协议，不补造计数、不抹除终态、仍须独立验证。

原生宿主工具并未被移除。WorkerTools 的使用仍依赖工作流约束；绕过入口、直接运行宿主命令或同用户修改账本不受本检测器保护。standalone 能直接拦截动态工具回调，原生路径不能宣称有相同强制能力。进展摘要不代替红绿验证报告，不扩大仓库、工具权限或发布授权。

## 本批运行边界

仅本地源码、合成夹具、测试和研发文档。没有修改个人配置、已安装技能、监控服务、实时账本或自动化，没有派发真实修复、创建原生聊天或执行上游写入。实际验证及回滚见变更记录；原生 App 长期运行和真实模型行为不是本批模拟测试的证明范围。
